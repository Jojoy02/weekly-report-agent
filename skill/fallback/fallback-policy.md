# Fallback Policy

仅采用 Condition → Action。

1. 如果来源周报不存在  
→ 提示提供来源材料，不进入生成流程。

2. 如果目标周报不存在  
→ 不生成目标结果，要求提供目标周报。

3. 如果无法确认目标周期  
→ 要求用户明确周期，不根据当前时间自行推断。

4. 如果来源事项无法匹配唯一项目  
→ 标记待确认，不自动创建或归类项目。

5. 如果关键日期缺失  
→ 不允许根据上下文推测日期。

6. 如果当前项目状态与历史状态冲突  
→ 阻断自动更新，展示冲突并要求人工确认。

7. 如果 Reference 加载失败  
→ 不执行依赖该 Reference 的自动判断，标记校验不完整。

8. 如果模型输出新增来源材料不存在的业务事实  
→ 删除新增事实并触发事实一致性失败。

9. 如果草稿未通过 Validation  
→ 禁止 Commit。

10. 如果用户仅回复“可以”“好的”“继续”“OK”  
→ 不进入正式写入。

11. 如果写入接口失败  
→ 保留最终确认稿，不重新生成，不改变业务内容。

12. 如果写后回读结果与确认稿不一致  
→ 标记写入异常并输出差异。
